Documentation

From agent output to bounded evidence.

This page gives the shortest coherent path through the current alpha. Repository documentation remains the exact implementation contract while the final documentation site is being assembled.

Quickstart

DiffWitness currently installs from a source checkout. It requires Python 3.11+ and Git, with zero Python runtime dependencies.

pipx install .
dw --version
dw doctor

dw doctor inspects your repository, suggests an evidence command and reports integration readiness. It does not execute your test suite.

Alpha distribution: the repository still uses a temporary public identity. Use the source checkout for evaluation; use a pinned tag or immutable commit when the first public package is released.

Mental model

DiffWitness separates four jobs that should never be blurred:

  1. Protect optionally handles bounded runtime actions while the agent works.
  2. Proof runs independent executable experiments after the change exists.
  3. Debt records unresolved engineering obligations and their repayment checks.
  4. IdleProof explains those facts without changing their evidence class.

The invariant: OBSERVED, SUGGESTED and UNKNOWN are never upgraded to VERIFIED by the interface or an LLM.

Choose a Protect mode

Live interception is optional and reversible. Inspect the environment before choosing:

dw protect detect

# DiffWitness owns supported hooks
dw protect enable --policy standard

# another harness owns live protection
dw protect use external

# no DiffWitness live interception
dw protect disable

All three modes retain Proof, Debt Ledger, Continuity and IdleProof. With current Codex builds, Codex feature, repository and hook trust remain controlled by Codex; DiffWitness never grants itself that trust.

Guard an agent

Wrap the interactive agent command you already use:

dw guard -- claude
# or
dw guard -- codex

Guard captures repository state before and after the session, keeps the agent interactive, then evaluates the exact resulting state through the same Gate used in CI.

Gate a change

dw gate --base origin/main --candidate HEAD

Gate first classifies the evidence situation. A documentation-only change does not receive a fabricated causal claim. Tests that also pass on the base are marked non-discriminating. A stable base-fail/candidate-pass contrast may enter real-hunk analysis.

Small changes can be searched exhaustively within configured bounds. Larger changes may use the budgeted Adaptive Core. Completeness and exhausted budgets remain part of the output.

Proof model

Contrast

Candidate evidence passes while the same candidate tests overlaid on the base fail. This distinguishes repair evidence from simple preservation.

Necessity

Actual production hunks are reverse-ablated. If evidence fails without a hunk, that hunk is necessary under this evidence and environment.

Sufficiency

Real-hunk subsets are added to the base to search for a bounded sufficient core.

Interaction

Individually removable hunks are tested together so mutually backing-up changes are not mislabeled as independent surplus.

Stability

Repeated, isolated executions must agree before stable causal labels are emitted.

DiffWitness does not prove the entire program correct, guarantee a globally minimal patch, turn Git worktrees into a security sandbox, or authenticate the author of a certificate.

Debt loop

Debt is represented as an explicit future obligation with stable identity, provenance and — when available — a replayable verification adapter.

dw debt
dw health
dw plan
dw repay --prompt-only
# or run the constrained mission
dw repay -- claude

Debt points are prioritization units. They are not bug probabilities, confidence percentages, CVSS scores or estimates of engineering hours.

IdleProof

The deterministic explanation is the baseline and needs no model, network or account.

dw explain
dw explain --json

# switch presentation, not truth
dw view guided
dw view technical

Optional wording layers may reuse an active coding-agent session, a local OpenAI-compatible endpoint, OpenRouter/BYOK, a custom gateway or finite managed AI on eligible Portal plans. Provider failure always falls back to deterministic output.

GitHub Action

- uses: actions/checkout@v4
  with:
    fetch-depth: 0

- uses: TFourniax/tooltest@main
  with:
    base: ${{ github.event.pull_request.base.sha }}
    candidate: ${{ github.event.pull_request.head.sha }}

Replace the temporary repository identity and moving branch with the final release tag or immutable commit once published.

Verify a certificate

dw verify evidence.json
dw verify evidence.json --against HEAD

dw note evidence.json --commit HEAD
git push origin refs/notes/diffwitness

A content change after proof makes the certificate stale. An identical proved Git tree may remain valid after commit because the binding is content-based.

Security boundaries

  • The test command is trusted code and runs locally with the invoking user’s permissions.
  • Git worktrees isolate candidate variants; they are not a hostile-code sandbox.
  • The core does not require source upload, raw prompts or a hosted DiffWitness account.
  • Protect receipts intentionally omit raw commands, source, prompts and raw agent-event streams.
  • The private planner, when enabled, is advisory and cannot mint or override proof.

Report potential vulnerabilities through the repository’s security policy.
