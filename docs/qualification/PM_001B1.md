## Explicit profile

The existing `project-event-1` envelope gains no mandatory field or schema change.
An event explicitly selects this profile through:

```json
{"provenance":{"producer":"diffwitness","source":"human-cli","diffwitness_profile":"project-memory-declaration-1"}}
```

`diffwitness_profile` is a reserved admission selector: absence retains legacy
validation; a present unknown or malformed version fails closed. This opt-in is
structural/semantic validation, not a signature, authenticated provenance or Proof.
It cannot convert an assertion into verified software behavior.

The descriptor returned by `dw state contract --json` lists profiles under the
additive `admission_profiles` member. Descriptor format and admission profile versions
are separate. Consumers should retain compatible unknown descriptor metadata while
requiring a recognized admission profile before interpreting its rules.

## Profile rules

All four event types require event status `DECLARED`, non-empty string provenance
`producer`/`source`, and a non-empty string actor `id`, in addition to the base actor
`kind` requirement. Required payload fields and permitted declaration edges are:

| Event type | Subject kind | Required payload fields | Predicate → target kind |
|---|---|---|---|
| objective.declared | objective | why: string/null; priority: low/normal/high/critical | served_by → component |
| decision.recorded | decision | why: string/null; alternatives: string array | motivated_by → objective; affects → component; created → debt |
| invariant.declared | invariant | why: string/null; critical: boolean | constrains → component; protects → objective |
| approach.failed | failed-approach | reason: string | informed → decision; affected → component; created → debt |

Relations may explicitly use `DECLARED` or inherit it from the current event. Neither
the event nor an edge can opt into higher authority through this profile. Additional
payload/provenance fields remain preserved; an explicit payload lifecycle must be
`active` or `inactive`, matching the current projection. Existing JSON, ID, byte and
batch limits remain in force. These checks establish shape, not the truth or usefulness
of a human's explanation; empty explanation strings are not silently rewritten.

The four native declaration commands opt in when appending new events. Their existing
options and output remain compatible. Human relation-only edits, Proof, debt and
understanding bridges retain their existing contracts until separate adoption work.
No other producer is silently reclassified as a declaration.

## Historical and cache compatibility

Unprofiled histories, including extension kinds/predicates and old free-form payloads,
retain their original acceptance and projection. New profiled events append to the
same chain. Old event bytes, IDs, hashes and authority are never rewritten to add a
profile. The descriptor remains broader than this first adopted producer profile.

Both journal and checkpoint readers validate explicitly selected profiles through the
same event-shape boundary. Invalid batches fail before append; invalid existing
profiled histories are rejected without repair. A new derived-cache anchor invalidates
stamps made before profile admission, so a JSON-only validation cache cannot bypass
the new rule. Valid legacy history is revalidated without changing the event journal.

This unit does not change dedupe semantics: a caller cannot mutate the provenance of
an already deduped event by selecting a profile later. Native declaration commands
already append distinct assertions; migration of other deduped producers remains a
separate adoption task. Complete lifecycle operations remain PM-006.

## Evidence and gates

The baseline accepts an explicitly marked objective.declared event with subject kind
decision and list-valued why; status stays DECLARED. This is the absence of the new
opt-in admission contract, not a newly demonstrated false VERIFIED. Initial six tests
produce 13 failed assertions and one missing-descriptor error before implementation.
Additional negative cases exercise each native payload type and relation boundary.
Two malformed-status cases separately reproduced unhandled TypeError exceptions
before the base event/relation status checks explicitly guarded string types. They
now produce the same controlled ContinuityError as other invalid statuses; valid
admission and historical status meanings are unchanged.

Regressions cover all four native producers, all-or-nothing batch rejection, journal
and checkpoint rejection with otherwise valid hashes, old-cache bypass, mixed legacy
and profiled history reconstruction, and independent descriptor metadata. Existing
Proof authority and exact historical JSON regressions remain gates. Installed wheel
and standalone binary journeys execute all four public declaration commands and
inspect their profiles/statuses. The 10k benchmark now explicitly selects this profile,
so it measures the new validation path as well as the same replay/recall budgets.

Required gates: targeted Continuity, full platform/package matrix, ProofBench,
ContinuityBench, integrated smoke, review, then fresh exact-main after qualified PR
merge. Exact SHAs, runs, artifacts and state transitions belong in #74. No HUMAN PASS
or full PM-001 completion is asserted.

## Boundary review

Validation performs bounded field/type checks on already parsed objects. There is no
dynamic schema execution, shell command, network call, new file path or Portal flow.
No raw prompt/source is added; only the explicit profile marker is newly persisted.
Errors identify the failed rule without echoing arbitrary payload values. The profile
does not authenticate a journal writer, and unprofiled compatibility is not a new
Proof boundary. Existing Proof/Guard authorization remains unchanged.
