# PM007 — explicit code bindings, drift and revalidation

Base: qualified Core `6ea6fbbec251fe06b55b7852ca7822b4b40705c4`.
Design recorded before implementation. This increment does not close full PM007.

An objective, decision, invariant or failed approach can be explicitly bound to
selected committed files and dependency manifests. The association and its reason
are DECLARED. File bytes come from hash-verified immutable Git objects using the
existing bounded reader. No parser, source cache, worktree snapshot, fetch, or real
index mutation is introduced. Commit references are resolved once; this scope is
committed code, never a claim about uncommitted changes or behavioral correctness.

`bind-code` creates the first reference. `drift` compares the retained reference
against an explicitly resolved commit (HEAD by default), reports changed, missing,
or unsupported paths, and preserves event/hash/commit citations. Dependency paths
are explicit selections, not a claim of complete transitive dependency coverage.
`revalidate-code` requires a reason and appends a new DECLARED reference; paths may
be explicitly replaced to accommodate a move; an unspecified role keeps its previous
selection. It never infers continued applicability,
confirms a lifecycle, merges identities, or transfers Proof authority.
Revalidation accepts `--clear-code` and `--clear-dependencies` for removing a role
explicitly after deletion; each conflicts with that role's path option. Clearing
both roles is rejected because a code binding must retain at least one reference.

The new opt-in profile uses a separate deterministic subject. It references the
exact current assertion and lifecycle revision, plus the previous binding. Ordered
journal admission rejects stale revisions, replaced bindings, unknown memories,
inactive memories, incompatible kinds and subject collisions, atomically. Strict
shape and ordered validation also apply to checkpoints/rebuilds. An old binding
whose assertion/revision is no longer current is explicitly stale. Older readers
reject the new profile; older-reader rollback is not assumed supported.

Bounds: 32 selected paths, regular files only when binding, 2 MiB per blob,
8 MiB total selected bytes, the existing tree entry/object/byte/depth limits,
15 seconds per Git command and 60 seconds total. Full journal validation remains
mandatory. No truncation can be interpreted as unchanged. No source text is added
to project history. Files under runtime metadata are not selected automatically.

Acceptance: real Git fixtures cover unchanged/edited/deleted/type-changed sources,
dependency drift, moved paths with explicit revalidation, non-ASCII paths, both
languages, lifecycle/identity isolation, stale concurrent writes, malformed and
hash-valid forged references, missing/corrupt Git objects, and budget failures.
Installed-consumer journeys must preserve the real index and worktree bytes.
Full base/optional suites, distribution build, review and fresh exact-main CI
remain necessary. This is MACHINE evidence; final coordinated HUMAN gates remain.
