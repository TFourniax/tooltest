# PM-012s — Atomic derived schema construction

Acceptance before implementation, 2026-09-18. Fresh main 660ffc3 test run
35345107320 failed on Windows/Python 3.12 and 3.13 at the unchanged 10s native
prompt limit. The existing diagnostic captured Python 3.12 inside
`continuity_state._schema` during `rebuild_state`. Python 3.13's UTF-8 protocol
test timed out without a child stack. Do not infer the same cause for that case.

The schema is currently built by an `executescript` without explicit transaction
control: every DDL statement commits independently. This affects a disposable
temporary database that is replaced only after reconstruction succeeds. Build
schema and event projection in one explicit transaction on that temporary file.
Keep SQLite's durable synchronization settings, journal verification, temp-file
replacement, prior-state preservation and the original test timeouts unchanged.

Regression-first rollback of the whole schema; one transaction spanning schema
and event rows; injected projection failure leaves the old state byte-identical
and no temporary database. Measure actual schema construction before/after and
repeat native/full continuity qualification. A local improvement or green rerun
does not prove every hosted timeout resolved. HUMAN NOT RUN.

Primary semantics: [SQLite transactions](https://www.sqlite.org/lang_transaction.html)
and [Python sqlite3 transaction control](https://docs.python.org/3/library/sqlite3.html#transaction-control).

Implementation adds BEGIN inside the schema script, leaving the existing
rebuild-state commit and atomic file replacement intact. Two reconstruction
regressions PASS; final complete continuity 130/130, native plugin 5/5 and native
UTF-8 3/3 PASS under their original limits. Exact remote matrix and fresh-main
results are linked from the canonical registry #74 and the enclosing PR.
