Provide confirm/reject/retire/supersede and history inspection for objectives,
decisions, invariants and failed approaches. Actions require an explicit reason
and append to the existing journal. They are DECLARED human judgments, never
executed Proof. Preserve the original assertion content and its own epistemic
status; expose lifecycle action, reason and provenance separately.

References bind the exact current assertion and lifecycle revision. Reject stale
updates, missing/wrong-kind/self/inactive replacement references and attempts to
overwrite an assertion after lifecycle management has begun. A superseded item
is terminal; create a distinct replacement rather than rewriting it. Reconfirming
a rejected/retired item is an explicit reconsideration, not proof of behavior.

Only active memory and edges with active known endpoints may seed current
context. History remains queryable, with bidirectional replacement references.
All readers/checkpoints/cache rebuilds must enforce the same transition rules.
Legacy histories remain readable, including their prior open extension syntax.

Required gates: regression-first public operations, lifecycle replay, immutable
supersession, stale concurrent updates, graph exclusion/reactivation, checkpoints,
cache invalidation, Guided/Technical and FR/EN parity, full CI and fresh main.
HUMAN NOT RUN until a real human executes the applicable release scenarios.

## Implementation and bounded review

The additive `project-memory-lifecycle-1` profile defines sixteen reasoned actions
over four kinds. Ordered admission validates the assertion and latest revision,
and pins the replacement assertion. Managed assertions cannot be overwritten;
superseded identities cannot reactivate. Unmanaged legacy histories retain their
existing interpretation. An action cannot attach arbitrary relations or upgrade
its declaration to VERIFIED.

The reconstructible database upgrades to `continuity-state-4`. A separate lifecycle
projection stores the review while preserving entity payload, authority and source.
The active relation view excludes known inactive endpoints. Current context and
default graph browsing use that view; explicit entity/history inspection retains
historical facts. Cache version/stamp changes force validated reconstruction.

Public existing declaration commands advertise and dispatch the lifecycle actions.
Guided context now includes failed approaches and assertion labels as well as the
DECLARED applicability review. FR/EN presentation leaves JSON facts unchanged.
No network service, new dependency, source-code persistence or Proof acceptance
change is introduced. This is applicability review, not code drift detection;
automatic drift and exact code-bound revalidation remain PM-007.
