# PM-009a — Read-only, cited history and relationship navigation

The baseline `fbebc797968014600c1b89aed603984e15f78d5c` rejects
`dw state history --help` with exit 2. Existing lifecycle-specific `show`, context
and the current graph remain useful, but do not provide general paginated original
entity history, direct source-event lookup or bounded bidirectional navigation
with each edge's exact journal citation.

## Scope and acceptance

Add three compatible `dw state` readers without changing the journal ABI:

- `history ID`: original subject events, newest first, with an identity/prefix-bound
  cursor. Appends may follow the captured prefix; truncation/divergent replacement
  invalidates the cursor. Whole events, at most 200 per page and 1 MiB compact JSON.
- `event EVENT_ID --hash HASH`: open the exact original cited record and optionally
  require the full cited SHA-256. Missing, ambiguous or mismatched sources reject.
- `why ID`: navigate latest recorded directed edges in both directions, retaining
  each edge's actual direction, authority, reason and event ID/hash. Defaults:
  depth 2/50 nodes/100 edges; hard maxima 4/100/200 and 8 MiB compact JSON.

Every invocation strictly validates one complete journal snapshot. Reads never
create/rebuild SQLite, append a record, execute project code, contact a provider or
send data externally. Original assertions and later applicability judgments retain
separate citations; inactive memory stays explicit. Unknown referenced entities do
not inherit another assertion's label/authority. Cycles and output truncation are
bounded and deterministic. Human output quotes recorded text and escapes terminal
controls/direction overrides; shortened reasons are marked. JSON retains original
history event content. English/French machine output stays identical.

## Evidence requirements

Required cases: immutable-prefix pagination across appends, exact whole-event byte
budget, invalid/identity-mismatched/truncated/divergent cursors, corrupt journal,
incoming/outgoing source preservation, latest-edge selection with historical source
retention, lifecycle source separation, unknown nodes, cycles, bounds, empty history,
non-repository CLI failure, text controls, exact-event/hash lookup and mutation-free
queries. The actual installed CLI journey creates declarations and relationships,
confirms/retires memory, resumes a pre-retirement cursor and checks every source
against the real journal. It runs through installed wheels and standalone binaries
in CI on Linux, macOS and Windows.

## Boundaries

This exposes recorded reasons, not invented or transitive causal Proof. Integrity
hashes do not authenticate an author. Inactive/active refers to the recorded memory
lifecycle and does not establish current committed or working-tree applicability.
Use existing explicit code drift/revalidation and exact-code Proof for those claims.
All latest recorded edges are navigable, including historical relationships to
inactive entities; earlier versions are available through their source events.

The complete journal scan remains O(history); output limits do not imply constant
time or bounded total journal size. No automatic source-code/refactor inference,
multi-writer reconciliation, normalized Portal history or arbitrary grounded Q&A is
added. Full PM-009 and the broader vision remain partial. All automated evidence
is MACHINE; final coordinated HUMAN and alpha/commercial release gates remain open.
