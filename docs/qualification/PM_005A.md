# PM-005a — conservative file relocation lineage (design gate)

Acceptance draft before implementation,2026-09-20. Owned development base
PM003b candidate421ae63; publication must use its qualified main and inherit
qualified PM012d if merged first. No new implementation/PASS claimed here.

Existing path/component IDs and commit.changed_files deliberately preserve
separate old/new paths. They do not record a durable relocation hypothesis.
Extend existing ProjectEvent admission/journal/projection; do not replace entity
identities, existing producers or feature-memory with a parallel ontology.

First scope: persist a narrowly derived link between one removed and one added
regular file with identical immutable blob content/mode in a captured commit's
first-parent transition. Require unique matching candidates and explicit
ambiguity/omission coverage. A coincidental delete/add can have equal bytes:
the relocation and all dependent identity links remain INFERRED, never VERIFIED,
authenticated authorship, actual runtime causality or automatic human acceptance.
Do not silently merge histories or transfer old Proof/applicability to a new path.
Symbol/feature identity after edits, copy/fork semantics and user confirmation
remain follow-up scopes rather than claims of complete PM005.

Potential integration: opt-in enrichment of existing bounded bootstrap pages,
separate typed immutable lineage observations per commit, existing atomic append
and dedupe, current component/file IDs retained as endpoints. Late opt-in must
work idempotently. A continuation must bind this additional policy and verify
the corresponding imported prefix, preserving old v1 cursor compatibility.
Do not implement before deciding total page relation/event bounds and cursor
migration. One command-level lineage history view should reuse these events.

Integrity design gate: raw Git diff output alone is not a verified association
between a path and a captured tree. Verify relevant immutable tree/blob objects
against their object IDs, with bounded paths/bytes/tree nodes/process time and
no replacements, lazy fetch, external diff, hooks or worktree/index mutation.
Oversized/ambiguous/non-UTF8/nonregular/symlink/submodule cases must not become
silently complete lineage. Preserve first-parent merge meaning and branches.

Required discovery and fail-before regressions: pure rename and move+edit,
duplicate-content ambiguity, copy, branch divergence, rename-back, mode changes,
root/merge/shallow boundaries, SHA256/Unicode, malicious/corrupted tree/blob,
raw-source exclusion, interrupted/concurrent retry, source byte cache corruption,
legacy cursor and late enrichment policy, immutable assertions/Proof authority.
Full/base/installed FR-EN,24+3/review/freshmain and unchanged budgets required.

Primary format references inspected: https://git-scm.com/docs/git-diff-tree
and https://git-scm.com/docs/git-ls-tree. A design draft is not qualification;
registry#74, complete PM003/PM004/PM005 and global/HUMAN/release gates stay open.

## Concrete implementation bounds and compatible cursor gate

Use explicit bootstrap `include_lineage=True` / `--include-lineage`, default
false. One additional `lineage.inferred` assessment per imported commit, using
an additive typed ProjectEvent profile and existing journal/projection. Its
separate `git-lineage:<commit>` subject prevents overwriting file assertions.
Up to32 unique old/new pairs; relations retain existing file and component IDs
as endpoints, plus the assessed commit (at most129 relations). At most300
specifications per100-commit page with both message and lineage options. No
implicit equivalence or lifecycle/Proof transfer; exact-byte matches are inferred
relocation hypotheses, not proof of intent or uniqueness beyond this transition.

Verify raw first-parent/current trees and traversed subtree object hashes. Walk
all entries, including unchanged ones for unambiguous scope; bounded per page
at32768 entries,512 distinct trees,16MiB raw tree bytes,64 levels. Validate tree
entry syntax/order/duplicate names/modes and reject malformed objects. Unsupported
UTF8/unsafe/oversized names and nonregular leaves are counted as exclusions;
coverage is explicitly limited when exclusions exist. Reject budget overflow
before journal append instead of claiming a truncated inventory complete.
Only unique removed/added equal-mode/equal-blob regular files are candidates.
Changed-in-place files, copies, edited moves, mode changes and duplicate matching
groups do not yield links. Verify matched blob object hashes (2MiB each,8MiB
aggregate page bytes). No raw content is persisted or fetched. All temporary
caches are invocation-local, keyed by verified object identities; no metadata
shortcut across calls. Existing15s Git/60s collection deadlines still apply.

Legacy no-lineage continuations remain byte-compatible cursor-v1. Opt-in uses
cursor-v2 binding include_lineage=true; changing policy requires restarting
idempotently. Every consumed row must also have matching validated lineage
assessment/commit/tree/first-parent bindings. Recomputed cursor checksum alone
cannot claim an unimported enrichment. First-parent continuation remains explicit
ref plus options; its generated hint must retain both opt-ins. Read-only
`dw state lineage --path` exposes exact event/commit citations with INFERRED
status, bounded results and scope/exclusion metadata, without chain collapse.
These bounds are first implementation acceptance, not performance qualification
of full32k trees, edited/symbol/feature lineage or complete PM005.
