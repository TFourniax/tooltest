# PM-012c — Byte-bound process-local append validation

## Scope and acceptance

Repeated append calls may continue a process-local validator only when the full
previously validated byte prefix is unchanged. Always read and compare actual
bytes under the journal writer lock; never trust size, timestamps, derived SQLite,
or serialized validator state. No validation state is persisted. Keep the current
strict parser, chain, dedupe, profile, ordered task and lifecycle checks.

The cache is private, bounded to one journal, 100,000 events and 128 MiB of journal
bytes. Larger histories use complete validation. Cached state must not alias caller
inputs or returned events. Take exclusive ownership and unpublish ordered state
before speculative suffix admission; failed validation or writes cannot publish
an unvalidated checkpoint. This satisfies speculative isolation without copying
the entire validator on every request. Concurrent
writers must see the actual journal, including appends from other processes. A
process restart or cache eviction requires complete validation.

Public verification, transport and reconstruction continue to validate the whole
journal. Budgets and deadlines remain unchanged. This unit does not qualify a
persisted validator, full PM-012, multi-emitter reconciliation, or the Alpha.

Required regressions: suffix-only validation counts; same-size/timestamp tampering;
valid divergent rewrite/truncation; external append; CR/LF and Unicode; caller
mutation; invalid lifecycle/task references after a cached prefix; partial write;
cache eviction/bounds; concurrent append; complete cold verification.

Measure the real existing 10k/50k/100k benchmark on baseline and candidate. Report
every budget failure. A cProfile diagnostic is separate from latency qualification.
Run full unit/package and exact-source PR gates, review, authorized qualified merge,
then fresh exact-main gates. All agent-produced evidence is MACHINE.

## Implementation and implementing-agent review

Only continuity_events.py changes production behavior. The private checkpoint
contains exact immutable journal bytes and the existing validator/dedupe state.
An append atomically takes ownership and removes the shared checkpoint before
reading. A complete byte-prefix match permits ordered suffix admission; otherwise
the existing strict rules run from the beginning. Only a successful durable write
publishes the next checkpoint. There is no serialized validator or SQLite trust.
Inputs and outputs are deep-copied at the public boundary. One checkpoint is
retained; the 128 MiB bound describes journal bytes, not total Python object RAM.
Cold starts and histories beyond either bound still require full validation.

Review found a related record-boundary case: a valid imported final record without
a newline was concatenated with the next event. The baseline regression fails;
the writer now inserts a separator while preserving all original bytes. Cache
reuse always requires a terminated prefix. CR, LF, CRLF, Unicode and blank lines
retain the strict reader's framing. No history, event ID/hash, authority, wire
schema, timeout, budget, or Proof semantics change.

This is implementing-agent review, not independent review or HUMAN PASS. Hostile
code executing inside this Python process is outside the cache trust boundary.
Existing journal locking and its stale-lock policy are unchanged. This does not
coordinate independent chains or binaries that ignore the lock.

## First PR Windows failure and correction

Candidate d9ca222 / tree 46f3719, PR #103, first test run 35402939988: all
four Windows Python versions FAIL three new assertions; 17 other jobs PASS.
The three companion workflows PASS. Failure blocks/job metadata are retained
in evidence/PM_012C_initial_PR_failure.json; no same-code retry was used.

Windows CRT O_TEXT translated os.write LF to CRLF, so the private checkpoint's
predicted LF bytes differed from disk. This safely caused complete revalidation
on every append but defeated suffix reuse. A deterministic CRT regression FAILS
on that candidate locally. The correction explicitly formats the existing native
record ending and uses O_BINARY, retaining Windows CRLF/POSIX LF and exact cached
bytes. It does not rewrite history or change event identities. The unterminated
fixture now strips CR and LF rather than leaving a valid CR terminator on Windows.
Thirteen new regressions and 156 Continuity cases PASS after correction. Fresh
full local and exact-source PR/main qualification are required again.
