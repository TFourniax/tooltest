# PM-P0-001 — Assertion-bound memory authority

Campaign baseline: `TFourniax/tooltest@f0d3515b9fd7d72e05e5560610faee5ff26196cf`,
tree `c7cd03d2050b1c46e40faf411277b1fa752da9e2`.

The single active coordinated registry and append-only qualification journal are
[issue #74](https://github.com/TFourniax/tooltest/issues/74). This document describes
the bounded defect and acceptance contract; it is not another release register.

## Reproduced defect

`_upsert_entity`, `_upsert_relations` and `_upsert_debt_open` retained the strongest
historical epistemic status while replacing content, provenance and the source-event
pointer. A prior VERIFIED assertion could therefore lend its authority to unrelated
new DECLARED content sharing the same identifier.

The public reproduction executes a real failing-before/passing-after unittest through
strict `dw guard`, producing an accepted causal Proof. It then runs `dw objective add`
with that certificate's identifier and a new invented label. The appended event is
DECLARED, but `dw context --json` returned the invented objective as VERIFIED.
The historical certificate itself was not altered. This is a false memory claim,
not a forged executable certificate. Exact baseline output is preserved in
`pm-p0-001-real-before.json`.

The same root affects replacement relation metadata and refreshed debt measurements.
A separate relation-only event also overwrote its source entity with a copied payload,
which could be stale and carried the wrong source-event provenance.

## Minimal correction

- Materialized replacement facts carry the replacing assertion's epistemic status.
- Replacement relation metadata carries the relation assertion's status.
- Refreshed debt measurements carry the refresh event's status.
- `relation.declared` materializes edges without reasserting/replacing the source entity.
- Derived state becomes `continuity-state-3`, forcing v2 caches to rebuild from the
  original validated journal, including the hot context-cache path.

`project-event-1`, the append-only journal, Proof certificates and the specialized
historical Proof records are unchanged. No model or runtime observation gains authority.
No cross-language extractor, ontology rewrite, identity policy or transport change is
included. Canonical typed entity identity belongs to PM-001, not this corrective patch.

## Regression evidence

`tests/test_continuity_memory_authority.py` contains six tests covering:

1. Replacements across five stronger-to-weaker epistemic pairs, with payload/provenance
   and source-event identity kept together.
2. A previously VERIFIED edge replaced by new DECLARED metadata.
3. Relation-only updates preserving the exact source entity.
4. Observed debt refreshed with an unobserved replacement measurement.
5. Automatic legacy-cache rebuild, deterministic replay and unchanged journal bytes.
6. Real executed Proof followed by public CLI ID reuse; the new fact is DECLARED,
   while the historical Proof row, envelope bytes and journal prefix remain unchanged.

Before product modification: 6 tests, 10 assertion failures (including subtests),
all corresponding to the reproduced defect. After correction: the targeted
`test_continuity*.py` suite passes 30 tests locally on Python 3.12.
Full exact-head CI and post-merge evidence are recorded in #74 and the PR, never inferred
from this local result.

## Security and performance boundary

The fix eliminates status/provenance laundering during projection and adds no external
input, shell invocation, network request or Proof-authority writer. All new test commands
run only on disposable fixture repositories. Removing status lookup queries reduces
projection work; correctness and corruption checks remain unchanged. The existing
10k ContinuityBench remains required. 50k/100k scalability is still PM-012.

## Human qualification

This change makes no new HUMAN PASS claim. Final Guided/Technical/native qualification
must use the exact coordinated candidate. Verify a real accepted Proof, inspect its
history, record a new declaration, inspect its DECLARED status through Technical/JSON,
and verify Guided does not imply the declaration was executed or proven. Historical
certificates must remain readable after upgrade and derived-cache rebuild.
