# PM-004d — Shared source-bound extraction transport

Acceptance written before implementation. Depends on PM-012c exact-main closure;
the branch may be prepared during its qualification but must not merge first.

The existing pure Python provider and FileExtraction remain the canonical substrate.
Expose a repository-independent, read-only `dw state extract --json` stdin/stdout
adapter for consumers such as IdleProof. The versioned request binds each relative
path to explicit source bytes (base64); output carries exact SHA-256, provider,
language, symbols/imports/calls and parse coverage. The adapter never opens supplied
paths, allocates Git identities, persists source, executes project code or grants
Proof authority. Unknown languages return file-level coverage without invented
symbols. No second parser or alternate truth model in this unit.

Bound admission to 64 unique relative paths, 1 MiB/file, 4 MiB total source and a
6 MiB wire request; reject duplicate JSON keys, noncanonical base64, unsafe/duplicate
paths, malformed fields and batches atomically. An empty batch is valid. Preserve
existing Python extraction results/IDs and all normal CLI behavior; JSON must be
identical in FR/EN. A malformed Python file has explicit unparsed status.

Required regressions: source/hash round-trip including Unicode, malformed request
matrix, bound enforcement, unknown/binary fallback, caller mutation isolation,
invocation outside Git with no file reads/writes and FR/EN parity. Add a real Node
consumer qualification invoking the installed Core adapter; later IdleProof adoption
must use this same transport and retain its existing source admission boundaries.

This is transport, not full PM-004. Language expansion (JS/TS, Go, Rust, JVM/.NET,
Ruby/PHP, SQL/config), consumer presentation and final human qualification remain
open; do not label unsupported-language fallback as semantic extraction.
Full local/package/21-job/companion workflow gates and fresh-main replay required.

## Local implementation and evidence

The new adapter delegates directly to extract_python and validate_extraction;
it serializes their immutable dataclasses. All source admission completes before
extraction. Response output is also bounded to 16 MiB before any stdout. The CLI
dispatches before repo_root; no storage/index/Git identity code is involved.
Core's existing Python IDs and structure projection are unchanged.

Five tests cover real CLI outside Git/FR/EN/no persistence, strict malformed-input
matrix, all byte/file/wire bounds, parse/fallback coverage and detached results.
Initial four tests: one missing-command FAIL, two missing-module errors; retained
in evidence. Actual Node invokes an isolated installed wheel and checks source
digest, names, authority, fallback and FR/EN parity. The same consumer is now in
integrated_product_smoke; installed wheel/binary language journeys also exercise
the protocol. These are MACHINE-operated journeys, not HUMAN validation.

First full source-path invocation used PM-012c's editable installation and triggered
installation-binding checks: 549 run, four failures/29 errors/four skips. All
failures were inspected; a separate exact-worktree editable installation corrects
the invocation without weakening runtime executable checks. Corrected initial
full: 549 run/four skips PASS. After adopting the PM-012c Windows correction and
adding wire-bound coverage: 551 run / 547 PASS / four Windows-only skips, 57.368s.
Compile, wheel, installed Node consumer and installed FR/EN journeys PASS.

Implementing-agent review: stdin framing is strict UTF-8/duplicate-key JSON,
source paths are labels only, base64 canonicality is checked by round-trip, and
errors never emit partial stdout. Source digests authenticate no binary/Git state.
Fallback never fabricates symbols or Proof. No independent/HUMAN review claimed.
Consumer adoption, additional providers and the complete PM-004 vision stay open.
