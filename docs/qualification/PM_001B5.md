## Acceptance contract

The six existing Debt Ledger lifecycle event types and `relation.declared`
select explicit admission profiles. Validate their consumed payload types,
source/subject identity, provenance and relation/status consistency. Ledger
acceptance and unacceptance remain DECLARED; other ledger observations remain
OBSERVED, including resolutions. A relation declaration remains DECLARED and
does not replace its source entity or inherit the source's Proof authority.
Profiles validate shapes and consistency, not the authenticity of assertions.

Preserve unprofiled histories and existing event/hash schemas. Compatible
legacy reimports must return the original event without changing bytes, ID,
hash or authority. Ignore only the additive profile marker after validating
both assertions; actual semantic differences must still conflict atomically.
Missing historical Git objects do not justify an invented change identity.

Reject consumed malformed source scalars before coercion or omission can hide
them. Keep existing bounded summaries and privacy boundaries. Journal readers,
checkpoint readers and context-cache admission must enforce the same profile.

## Required qualification

Reproduce missing native profiles and malformed-source admission on baseline.
Exercise the actual six-state ledger producer, idempotent legacy reimport,
public relation command, mixed replay, checkpoint validation, stale-cache
invalidation and atomic invalid-batch rejection. Run focused regression tests,
complete platform/package gates, ProofBench, ContinuityBench, integrated native
journeys, review and fresh exact-main qualification after merge.

HUMAN PASS means a human tested and validated the scenario in real conditions.
Automated tests and agent-operated journeys are MACHINE evidence. Record human
tester, date, scenario, environment and exact candidate before claiming a pass.
Historical human evidence remains historical. All release-required scenarios
without applicable human validation must be validated before an Alpha release.

This bounded unit does not complete cross-product identities, durable task
causality, richer memory lifecycle operations or coordinated Alpha qualification.

## Bounded review

`project-memory-debt-lifecycle-1` and `project-memory-relation-1` share the existing
admission boundary. Legacy/profile migration validates both assertions before
ignoring only the marker. Cross-profile versions and real changes still conflict.
The derived digest key changes so the prior validator's cache cannot bypass these
rules. No event/state schema migration or historical rewrite is needed.

Source validation precedes bounded projection. Existing null/absent fields and
zero points retain their semantics; unavailable historical base objects yield no
change relation. Verification maps retain their existing bounded scalar summary
policy; this is not full validation of the legacy Debt Ledger wire format. Batch
admission is atomic within each existing synchronization batch, not a transaction
over arbitrarily many batches. Existing batches and event limits remain.

No new dependency, network destination, source/prompt persistence, Proof authority
or extra journal scan. Checks are linear in each bounded payload. The existing
10k benchmark covers the broader cache/journal budget; it does not establish
50k/100k scalability or a statistical improvement for this change.
