# PM-001b4 — Typed artifact events and compatible history

Baseline: `TFourniax/tooltest@ade47efb468ec45752fe0df40abe0fa5fd424302`,
tree `81611f716076c6e0de97d6d41229f08f35d559dc`.
The canonical registry and append-only qualification journal remain
[issue #74](https://github.com/TFourniax/tooltest/issues/74).

## Contract and compatibility

The existing envelope bridge now selects `project-memory-artifact-1` for its five
event types: change.observed, proof.completed, debt.snapshot, debt.observed and
understanding.recorded. The shared admission boundary validates required payload
types, producer/source/schema, actor identity, subject/payload/relationship bindings
and epistemic consistency. Discovery exposes fresh metadata for the same live rules.
The profile does not implement full source-envelope JSON Schema validation.

All non-Proof events remain OBSERVED. A Proof event's accepted flag and existing
authoritative-validation flag determine its status, with consistent payload,
provenance and relation metadata. Manual imports cannot set that runner flag.
A profile or self-asserted flag does not authenticate a certificate. The existing
Guard/native runner remains the authority boundary; no new authorization is added.
Consumed source and caller scalars are checked before string/boolean projection.
Optional absent summaries/fields retain their existing defaults.

Legacy unprofiled events remain readable, including extension histories. An
unprofiled/artifact-profile pair may ignore only that marker for deduplication,
and only if both assertions validate under the artifact profile. All other semantic
fields still match. Existing envelope-digest and ephemeral change-SHA exceptions
remain unchanged. Unknown or cross-profile versions are not migration shortcuts.
The original event, ID, hash, provenance and bytes are returned unchanged; no
historical event is silently upgraded or retroactively profiled.

Semantic comparison uses canonical finite JSON instead of Python container equality.
Boolean versus number, nested type changes and integer versus floating serialization
now conflict, including extensions. Object key order remains immaterial. Conflicts
within a batch or against old history reject the entire batch before append.

Journal and checkpoint readers apply the same validator. The derived cache digest
key changes so caches validated only against the older declaration profile cannot
bypass the new artifact rules. Event/state schemas and existing journal bytes do
not change; derived state remains rebuildable.

## Qualification

The initial eleven regression tests on unchanged baseline produce 50 failed
assertions and six errors (including unsupported artifact-profile admission).
They reproduce native missing profiles, incompatible legacy reimport, JSON type
collisions, consumed-scalar coercions and the old-cache admission bypass.
Additional tests cover the public native reimport, invalid legacy fields behind
dedupe exceptions, declaration conflicts and atomic relation-metadata conflicts.

Required gates: targeted and complete platform tests, installed package/standalone
journeys, ProofBench, 10k ContinuityBench, integrated native artifact journey,
implementing-agent review, and fresh exact-main after any merge. Exact runs,
SHAs, artifacts and failures belong in #74. HUMAN qualification is separate.

## Bounded review

No new dependencies, network destinations, Portal fields, raw prompt/source
persistence or journal rewrite. Additional work is linear in the bounded event
payload; compatible profile adoption validates two existing assertions only on
duplicate keys. No extra journal scan is added. Existing event/batch size caps and
cryptographic history checks remain. Self-asserted histories remain self-asserted.

This unit does not complete the Project Memory ontology, debt lifecycle/relation-only
profiles, common Core/IdleProof identities, multi-writer convergence, or Alpha release
qualification. Those remain separate items in the canonical registry.
