# PM-002c — Native UTF-8 task protocol

Acceptance before implementation, dependency PM-012n #97. Actual Node → Core
Unicode prompt parity still fails after sidecar prefix/scalar alignment: Windows
Core reads UTF-8 JSON bytes as cp1252 and hashes altered text. The standalone
plugin also inherits locale output encoding. Existing ASCII-escaped fixtures
conceal both defects.

Read native JSON bytes explicitly as strict UTF-8 in both adapters through one
reader. Retain in-memory text-stream compatibility; reject invalid UTF-8 instead
of replacing bytes. Configure standalone plugin output through the existing Core
UTF-8 output routine. Preserve JSON shape/error behavior, bounds, task-v1 IDs,
source authority and the raw-prompt privacy boundary.

Require actual subprocesses forced to cp1252 with unescaped UTF-8 payloads for
public CLI and plugin: exact native task ID, prefix length/digest and complete
Unicode output. Retain invalid-byte/no-object/TTY rejection. Existing native and
full remote gates, actual Node/Core parity and fresh-main qualification required.
All tests MACHINE; HUMAN NOT RUN. No historical task record is rewritten.
