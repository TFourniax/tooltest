# PM-008a1 — Citable memory assertions

Acceptance before implementation, 2026-09-18. Context memory items expose current
labels/status/details but not the exact assertion event that produced each item.
Add an additive `source` reference to selected objectives, tasks, decisions,
invariants and failed approaches: the ProjectEvent ID and event hash. Resolve it
from the same SQLite snapshot used for the item. A later unrelated journal event
or an applicability confirmation must not be misreported as the assertion source.

The packet's existing `state.eventHead` remains its journal snapshot anchor. Do
not claim the packet is current after that snapshot, that a source hash authenticates
an author, or that a declaration is code-revalidated. Preserve entity status and
separate lifecycle-review references. No raw author/provenance metadata is added.
Missing or inconsistent source rows must fail visibly instead of manufacturing
a citation. Existing versioned contexts remain additive/backward-compatible.
The reference identifies current details/status. Historical declarations may
inherit a display label; per-field legacy label lineage is outside this unit.

Tests must cover exact citations through declaration replacement, unrelated
appends, lifecycle confirmation, state reconstruction and cached compilation;
old citation immutability; missing source failure; unchanged status and no raw
metadata projection. Verify indexed selection stays bounded and existing context,
native, transport and consumer journeys remain compatible.

This closes per-assertion citation only. Code-bound drift/revalidation, citations
for all structure/Proof/debt surfaces, FR/EN retrieval quality and whole PM-008
remain separate acceptance. MACHINE tests do not create HUMAN PASS.
