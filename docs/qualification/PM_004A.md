# PM-004a — Provider-neutral extraction boundary

Acceptance before implementation. Dependency Core #98 (UTF-8 native boundary).
The existing Python AST extractor mixes parsing, identity allocation and SQLite
insertion. Isolate its source analysis behind a versioned, immutable result
contract so later language providers can reuse one materializer and authority
policy instead of introducing unrelated stores or IDs.

Preserve existing Python component/symbol IDs, qualified names, import resolution,
OBSERVED AST facts and INFERRED name-call heuristics. No provider may emit VERIFIED
or DECLARED structural facts. The coordinator owns the captured Git tree, source
path and digest; a provider result for another path/source must be rejected before
replacing the current index. Source budgets and dirty/untracked isolation remain.

Separate parse failure/coverage from provider contract violations. Unsupported or
unparsed files cannot fabricate symbols; violations must fail visibly. Invalidate
derived state when the provider contract changes. Tests must cover actual Python
classes/async methods/imports/calls, syntax/UTF-8 failures, exact source binding,
authority rejection, pre-write validation, and existing immutable-tree/continuity
behavior. Full remote gates and fresh-main qualification required.

This is the Core extraction adapter, not full PM-004 acceptance. IdleProof's local
working-tree feature heuristics remain available; a shared export adapter and
additional language providers follow. No claim of a runtime call graph or HUMAN
qualification. Canonical status remains in registry #74.
