One instrumented 2,000-event synthetic run shows generic `copy.deepcopy` spending
0.278 seconds cumulatively out of 0.560 seconds in append (1.213 seconds for the
whole benchmark). These profiler timings are diagnostic, not release latency.
Append detaches both caller-owned event data and public results to protect the
private, byte-bound validator checkpoint. Both ownership boundaries must remain.

Try a specialized copy for exact built-in JSON dictionaries, lists and immutable
primitive values. Preserve aliases and cycles with a fresh memo per operation;
delegate tuples, subclasses and other values to the existing deepcopy using that
same memo. Do not normalize types, reuse caller-owned mutable containers, alter
event encodings/IDs, add a parser, or change any journal-byte admission/checkpoint
rule. If the measured cost does not improve, do not ship this optimization.

Acceptance: copy-equivalence and isolation including aliases, cycles, subclasses,
tuples and negative zero; existing input/result mutation, corruption, concurrent
append, lifecycle and checkpoint regressions; full base/optional suites, compile,
installed exact wheel and integration. One parent and one candidate run per size
(10k, 50k, 100k) with the existing gates unchanged, plus explicit retention of
every failure. Existing 10k thresholds at larger sizes remain discovery rather
than a newly agreed SLA. This does not solve persisted incremental validation,
monorepo or Windows qualification, and does not close full PM012.
