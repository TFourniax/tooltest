# PM-001b3 — Exact source-byte provenance for envelope imports

Baseline: `TFourniax/tooltest@ea4e5f28c44501de958380aa920de18d9cb94155`,
tree `1adaec1c90e496efaa447f17c987f7d0d5d5c1a7`.
The sole active coordinated registry and append-only journal remain
[issue #74](https://github.com/TFourniax/tooltest/issues/74).
This is a bounded provenance correction, not full PM-001 or HUMAN qualification.

## Reproduced mismatch

The importer parsed a file, resolved Git bindings, then reopened the path to compute
artifact_digest. Replacement between those reads could bind facts from the first
version to the second version's digest. Deletion could drop source provenance entirely.
A deterministic replacement on the baseline records accepted=true / OBSERVED while
the referenced bytes contain accepted=false. This does not demonstrate a new false
VERIFIED or a forged Proof certificate; it demonstrates an incorrect source reference.

## One byte snapshot

The reader now reads raw bytes once and derives both the parsed envelope and SHA-256
digest from that same buffer. Strict UTF-8/JSON validation remains in place. The digest
identifies the original serialization, including Unicode encoding, whitespace and
CRLF/CR/LF line endings, rather than a canonicalized object or a later file version.
Subsequent source replacement/deletion cannot rebind or erase that provenance.

A direct in-memory import has no source-file digest. If a caller supplies both an
object and a path, the parsed source must match the object's canonical JSON content;
otherwise admission fails before append. Missing, malformed or ambiguous source files
cannot be bypassed by supplying a separate object. Equivalent serializations match,
but their source digest still identifies the exact bytes read. Current product callers
use path only; valid object-only and matching object/path calls remain supported.

The importer does not retain a permanent copy of the source file or certify that its
path still contains those bytes. It records which bytes were observed. Existing
semantic dedupe ignores alternate envelope serializations, so an equivalent reimport
reuses the original immutable event and its original source reference. No journal byte,
event ID, hash, schema or prior authority is rewritten; historical provenance is not
retroactively repaired or invented.

## Qualification and boundary review

Five regression tests initially fail eight assertions on the baseline. They cover
replacement/deletion after parsing, conflicting dual inputs, missing/malformed source
files, exact Unicode/newline byte digests, equivalent reimport idempotency, and direct
object imports without invented file provenance. Races are scheduled deterministically
at the existing between-read boundary, not with timing-dependent sleeps.

Required gates: targeted and full tests across the supported OS/Python matrix,
installed wheel and standalone native journeys, ProofBench, ContinuityBench, integrated
smoke, implementing-agent review, then fresh exact-main after qualified merge. Exact
SHAs, runs, artifacts and status transitions belong in #74; no HUMAN PASS is inferred.

The change removes the second source-file read and existence check. It adds no network
path, Portal data, runtime dependency, raw prompt or source persistence, shell command
or Git ref mutation. Both file facts and provenance now share one read result. Dual
input comparison adds canonical serialization only for callers using both parameters.
Existing input-size and journal-scaling behavior are not expanded or claimed solved.
Digest consistency is not authentication or authorization to emit VERIFIED: manual
imports remain OBSERVED and the existing authoritative Proof runner boundary remains.
