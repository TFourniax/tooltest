Baseline: `TFourniax/tooltest@6b8632a3921c2f00d33e6157e732c9d3a1625d61`,
tree `aecebd681216f7400d897a538a5688a0d60bc58a`.

This file specifies this bounded acceptance contract, not the release status.

## Demonstrated gaps

The local ProjectEvent reader and Git checkpoint reader silently accepted duplicate
JSON members, including nested and escaped equivalent keys. Canonical hash validation
then checked the parser's chosen last value, without rejecting the ambiguous input.
The reproduced duplicated epistemic field still parsed as DECLARED: this task does
not claim another demonstrated false VERIFIED.

The writer also admitted NaN and infinities, including nested measurements, and both
readers accepted those non-standard values with valid hashes produced by the old
serializer. A large numeric exponent could overflow to infinity. A cache populated
under that permissive parser could bypass new parser checks unless its validation
anchor was invalidated.

Separately, checkpoint `splitlines()` treated U+2028, U+2029 and U+0085 inside valid
JSON strings as event delimiters. An event admitted locally therefore failed to
round-trip through its checkpoint. Both readers now use CR/LF framing.

## Compatible correction

- Extract the existing local configuration strict parser into `json_contract.py` and
  reuse it for ProjectEvent and checkpoint admission. Configuration retains its
  existing helper alias, errors and validation policy. The engine response protocol
  and its authority checks are unchanged.
- Reject duplicate members at any nesting level and non-standard numeric constants.
  Finite canonical serialization also rejects overflow to infinity, before any event
  in an invalid batch is appended.
- Reuse the journal's canonical serializer for checkpoint output. Valid historical
  serialization, event IDs, hashes, ordering and `project-event-1` remain unchanged.
- Use a new derived-cache metadata key so anchors created by permissive parsing are
  not treated as strict-validation evidence. Valid journals are revalidated without
  rewriting history; ambiguous/non-finite histories fail closed and are left intact.
- Preserve literal Unicode string content while supporting LF, CRLF and CR framing.

No new ontology, producer, authority source, project-memory transport format or LLM
capability is introduced. The canonical entity/relation/provenance/lifecycle work and
compatible producer adoption remain separate PM-001 units.

## Regression evidence

`tests/test_continuity_json_contract.py` covers nested and escaped duplicate members,
finite-only atomic batches, non-finite old histories with valid old hashes, exponent
overflow, old-cache invalidation, actual Git checkpoint restore rejection with an
unchanged local journal/ref, historical reconstruction and Unicode transport.

The initial six tests produced 23 failing assertions on the baseline. A seventh
test separately reproduced the Unicode transport error before that correction.
The fixture `tests/fixtures/project-event-1-valid.jsonl` was generated by the baseline
before product changes. Its event identity is `dwev_57a6317565c3dd085cc27f4f` and its
event hash is `a65eec929f19e2770c14e329ad21abe309744725a133b5d89aed08bd7e73b90e`.
The new writer must reproduce its JSON bytes exactly, retaining the baseline
writer's native journal line ending (LF on Unix, CRLF on Windows). Fixture checkout
line endings are normalized before constructing that expected output and each
explicit LF/CRLF/CR reader case. Rebuild/transport must retain identity and authority.

Required gates: targeted Continuity/config compatibility, full unit/platform,
distribution and installed journeys, unchanged 10k performance budgets, ProofBench,
integrated smoke, and fresh exact-main qualification after qualified PR merge.
Current SHA, workflow and artifact results belong in #74. No HUMAN PASS is asserted.

## Boundary review

Parsing uses the standard JSON decoder with explicit duplicate/numeric rejection;
there is no executable deserialization, shell, network, credential or Portal flow.
The added validation does not confer Proof authority. The failed batch and restore
tests check that rejection cannot partially append or normalize away ambiguous
history. Journal contents are never repaired silently.

Existing history-scale limitations and raw input/resource limits are not redefined
by this task; PM-012 remains open. Invalid legacy journals are deliberately rejected,
not migrated by changing their hashes or epistemic meaning. Human qualification of
the final coordinated candidate remains separate from these machine results.
