# PM-012b — Incremental projection after complete journal validation

Base: Core `4f8f9b12f19fff7860ec7bfed4c885971a0e0cb5`, tree

## Bounded objective

1. Validate each existing journal event once per append operation. Continue the
   same request-local validator through the new batch, retaining hash-chain,
   dedupe, task-reference and lifecycle-revision state. Never persist or reuse a
   validator across calls; invalid batches must append no bytes.
2. On a materialized-state update, strictly parse and validate the complete
   journal bytes. For a compatible derived database whose event rows form the
   exact validated prefix, apply only the suffix in one durable transaction.
   Reuse the existing projectors and lexical index; keep Proof authority intact.
3. Serialize derived-state updates and explicit rebuilds with a separate local
   state lock. Read the journal after acquiring that lock. Commit projected rows,
   count, head and exact validated byte digest together. Readers see a SQLite
   snapshot; failed updates roll back. A later journal append/corruption must be
   detected by the next request, never stamped from a second unvalidated read.
4. Missing, incompatible, divergent, truncated or structurally damaged derived
   state falls back to atomic reconstruction from that same validated snapshot.
   Explicit rebuild stays available. Preserve valid Git structure indexes during
   suffix application and refresh them through the existing freshness rules.

This deliberately retains O(history) strict validation on every append/update
and full-byte SHA-256 checking on hot context. No mtime/size shortcut, persisted
validator, second journal, new event format, timeout increase or weakened budget.
Arbitrary hostile modification of all derived-cache rows/anchors is not made
cryptographically authentic by this change; the existing disposable-cache trust
boundary remains. PM-012 as a whole, larger-history admission budgets and final
HUMAN qualification remain open.

## Required evidence

- Failure-first operation-count regressions: one history validation per append;
  one journal parse per state update; no prefix projector calls on valid append.
- Incremental/rebuild equality for entities, lexical terms, relations, lifecycle,
  tasks, changes, Proof, Debt and understanding; exact citation/status parity.
- Same-size/same-mtime corruption, hash-valid invalid historical references,
  invalid batch atomicity, stale lifecycle, dedupe/conflict, CR/LF/Unicode framing.
- Divergence, truncation, deletion, old schema/anchor and damaged rows rebuild;
  interrupted projection preserves prior state and retry converges.
- Deterministic append-after-snapshot, concurrent materializers/rebuilds and
  reader-snapshot schedules; existing integrity/concurrency regressions retained.
- Sequential same-host baseline/candidate samples at 10k/50k/100k, including
  append-one + ensure-state on an already materialized history. Use unchanged
  existing 10k limits at all sizes and report any larger-size failure explicitly;
  no statistical/general hardware performance claim from these local samples.
- Existing full suite/package gates, 21 test jobs and ProofBench, ContinuityBench,
  integrated-product-smoke on exact PR; fresh exact-main gates after merge.

## Implementing-agent review (MACHINE, not independent or human review)

- The event validator is the existing validation loop moved into request-local
  state. Reader/checkpoint admission retains the full loop; appending continues
  the validators obtained from the same strict read under the existing event
  lock. Nothing seeds a validator from SQLite, file metadata or a cached digest.
- The event insert and three existing projectors are shared without changes to
  their authority semantics. All prefix sequence/ID/hash rows, count, schema and
  head must agree with the fully validated history before suffix projection.
  Raw-byte changes without semantic changes still receive the newly validated
  byte digest, never a reread digest. Schema version 6 remains compatible because
  the persisted tables and projection semantics do not change.
- SQLite rows and anchors commit together; exceptions close/rollback the active
  transaction. Corrupt/incompatible derived state rebuilds atomically from the
  same validated snapshot. Busy/locked, disk-full and I/O errors propagate instead
  of silently replacing a database. The explicit busy-writer regression covers
  this boundary with a reduced test-only wait; product waits are unchanged.
- State and journal locks are separate. State writers read after acquiring the
  state lock; concurrent legitimate journal appends are caught by the next full
  byte check. Reuse the existing 10s acquisition/120s stale-lock policy. This
  does not establish indefinite-lock leases, independent-chain reconciliation or
  coordination with older binaries that do not take this new state lock.
- Context's hot byte-hash path stays unchanged. Structure refreshes that write
  now enter the serialized materializer; current structure reads remain cheap.
  No new dependency, network call, raw prompt persistence or private payload is
  introduced. Complete source status/citation and lifecycle checks remain active.
- Current local full suite: 533 tests run, 529 passed, four Windows-only skips,
  57.721s. See the journal for the earlier PATH failure and scheduler-fixture
  adjustment. Qualification on other operating systems remains a remote gate.

## Sequential same-host diagnostic

Three real append-one/update samples per size, with complete logical-table
equality against reconstruction at each size. Medians below are seconds. Fixture
seeding is excluded from these timings; it is explicitly not a product append
measurement. Baseline and candidate ran sequentially. The machine is not isolated,
so these ratios describe the samples, not general latency guarantees.

| Existing events | Append one before | Append one after | Materialize before | Materialize after |
|---|---:|---:|---:|---:|
| 10,000 | 0.685099 | 0.356874 | 1.344534 | 0.382564 |
| 50,000 | 3.655687 | 1.989240 | 8.333882 | 2.031489 |
| 100,000 | 7.366227 | 3.921004 | 16.371508 | 4.109513 |

The baseline projects the entire history on each append. The candidate projects
exactly one event in each of these nine updates while still validating all events.
Observed update ratios are 3.5–4.1x; the remaining linear cost is visible. This is
not qualification of a 100k latency budget. Full benchmark failures are preserved
in the separate unchanged-budget artifacts, alongside the passing 10k gate.
