# PM-P1-001 — Validated snapshot cache anchors

Baseline: `TFourniax/tooltest@18c6a052c23a4548f3c2fd4a9037b535508960dc`,
tree `92121c3f9fee6fd27522747c66957c66d9d5d6cc`.
The sole active registry and append-only qualification journal are
[issue #74](https://github.com/TFourniax/tooltest/issues/74).
This file is the defect/acceptance contract, not a second status register.

## Reproduced gap

The context cache strictly validated/materialized the journal, then separately read
the current journal bytes to establish its trusted SHA-256. Those operations could
observe different snapshots. A real append between them remained absent from later
contexts, indefinitely until another invalidation. Corruption at the same boundary
also acquired a trusted digest: the next context succeeded while a strict journal
read rejected the chain. The events were not physically deleted and no executed
Proof certificate was forged.

`pm-p1-001-cache-before.json` records both schedules on the baseline. The fixture uses
disposable repositories, the real event writer and compiler, and a wrapper that
controls only when the append/corruption occurs. It does not substitute validation
results. This is a P1 integrity/freshness defect in advisory memory, not a new Proof
authority mechanism.

## Correction

`read_project_event_snapshot` hashes the same raw bytes it parses, validates the full
existing chain and returns the events with that digest. LF/CRLF/CR and whitespace are
hashed as read; event IDs and hashes retain their existing canonical representation.
`read_project_events` keeps its existing list-returning API.

Reconstruction stores the validated digest alongside the corresponding event head,
inside the newly materialized database. Reuse of an existing state writes the digest
only if its schema and event head still match inside the SQL write operation. A
concurrent replacement cannot inherit a different snapshot's stamp.

Context only compares current bytes with this validated anchor. It never establishes
an anchor from a second unvalidated read. A new metadata key invalidates stamps made
by older versions, including poisoned stamps. The journal and state table schemas,
Proof certificates and agent/Portal payloads remain compatible.

## Acceptance and limits

Regressions cover cold and previously cached append/corruption schedules, unsafe old
cache migration, exact CRLF/whitespace byte binding with mutation during validation,
concurrent reconstruction, and preservation of the hot path without reparsing.
The initial five new tests produced six failing assertions on the unchanged baseline;
the no-reparse test already passed. The additional concurrent-rebuild regression
protects the conditional stamp operation.

A context is a point-in-time view identified by its event head. A writer may change
the journal after that snapshot is validated; the following context must validate
that change, not treat it as already checked. This correction does not claim a global
transaction across the journal, filesystem, all context queries and malicious direct
SQLite writes. Multi-writer convergence remains PM-011.

Required MACHINE gates: targeted Continuity regressions, full unit/platform and
package/installed/native matrices, 10k ContinuityBench with existing budgets,
ProofBench, integrated smoke, followed by exact-main reruns after PR merge.
SHA/run/artifact results belong in #74. No HUMAN PASS is asserted. Final coordinated
human qualification must confirm a declaration added from another session appears
on the next context request and an integrity failure is never rendered as success.

The correction adds no shell, network, credential, entitlement or Portal boundary.
Raw bytes are hashed while streaming existing parsing; no extra full-journal buffer
is introduced. Hot context remains one streaming digest comparison, without full
replay. 50k/100k performance and multi-writer reconciliation remain separate tasks.
