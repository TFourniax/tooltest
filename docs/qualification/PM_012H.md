# PM-012h — Canonical validation without repeated payload encoding

Baseline: `fbebc797968014600c1b89aed603984e15f78d5c`.
All observations in this change are MACHINE evidence. Full PM-012, the historical
IdleProof macOS provider failure and coordinated alpha readiness remain open.

## Demonstrated cost and bounded change

The existing complete validator serializes every event payload three times: for
the canonical event-size check, event ID and event hash. A diagnostic 100k profile
attributes 11.302 seconds cumulatively to 1,800,016 JSON dumps across the entire
benchmark; profiler timing is not a latency qualification. The operation-count
regression on the isolated baseline fails with three payload encodings versus one.

For ordinary decoded JSON events with correctly shaped identity strings, encode
the sorted members on each side of `event_id` once. The original event-ID input
joins those partitions. The original event-hash input inserts the exact ASCII
event-ID member between them. Calculate the full canonical UTF-8 size including
the event-hash member and LF. Every actual event ID and hash is still recomputed
and compared; stored values do not qualify themselves. Nonstandard Python mapping
inputs and malformed identity strings retain the existing encoding path.

No journal bytes, IDs, hashes, profile rules, authority, task/lifecycle reference
validation, locks, deepcopy behavior, checkpoint protocol, persisted cache,
dependency or performance budget changes. This is separate from withdrawn #116.

## Acceptance

- Independently computed canonical size and digests agree for nested values,
  Unicode, escape sequences, numeric values, insertion orders and unknown extension
  members on either side of the identity fields.
- Corrupted payload/authority/previous hash/ID/hash, nonfinite values and circular
  references still reject. Exact UTF-8 size boundary remains enforced.
- Existing strict JSON, history, append alias isolation, cache corruption,
  checkpoint transport and reconstruction tests remain required.
- Installed CLI suite, exact PR checks and subsequent fresh main checks remain
  required. Optional-provider skips are reported separately.
- Measure a fixed three-pair sequence at 10k, 50k and 100k, alternating pair order,
  with unchanged benchmark arguments and budgets. Retain every outcome, including
  the initial unpaired measurements. Shared-host results are diagnostics, not an
  SLA, and a remaining failing budget must not be reported as qualified.

## Initial evidence and invocation correction

Seven targeted tests pass, including 200 reproducible independent-encoder cases.
Initial unpaired 100k baseline/candidate: append 10.905429/10.180873 seconds,
verify 4.130025/3.288337, rebuild 11.381243/10.378223. All three budgets still FAIL
for both sources. Hot context p95 58.124/60.823 ms passes its unchanged 300 ms bound.

The first full-suite invocation used the system interpreter with source PYTHONPATH
but without this installation's CLI entry points. It ran 681 tests and failed with
10 failures/29 errors/52 skips; diagnostics identify missing installed `dw` and
`idleproof` entry points. That unsuccessful invocation is retained. The corrected
invocation with the existing Core virtual environment and absolute PYTHONPATH also
failed (4 failures/29 errors/52 skips): the source `diffwitness.egg-info` shadowed
installed distribution metadata and contained no executable RECORD entries. The
metadata path and empty entrypoint list were directly observed. A fresh candidate
wheel is therefore installed in an isolated environment and tested without a
source PYTHONPATH. Both `dw` and `idleproof` resolve to that installation, and its
imported validator is the wheel file. These are environment corrections, not
product changes or erased test failures.
