## Consumer interface

```sh
dw state contract --json
```

This read-only command works outside a Git repository. Its JSON is identical under
English and French presentation. It returns `project-memory-contract-1`, describing
the existing `project-event-1` envelope. Python consumers can call
`diffwitness.continuity_contract.project_memory_contract()`; each call returns fresh
JSON-compatible data without reading a repository, user preferences or credentials.
An unknown descriptor version must not be assumed to have version 1 semantics.

The descriptor exposes the canonical vocabulary, actual wire syntax/size limits,
provenance conventions, authority boundaries, current lifecycle projection and
compatibility policy. It does not assert that every named kind has a native producer
or a complete user workflow. No event gains authority by appearing in this vocabulary.

## Vocabulary and compatibility

The primary concepts are task, objective, decision, invariant, failed approach,
feature, component, symbol, dependency, change, proof, debt and understanding.
Wire spellings use `failed-approach` and the existing `proof-certificate`.
Legacy `file` and structure-provider `external-module` names remain discoverable.
Producer identities are preserved; this unit introduces no common cross-provider
feature identity or automatic kind alias conversion.

Known relations include the existing human declaration predicates and producer
predicates such as `served_by`, `affected`, `proves`, `describes`, `refreshed_in`,
`reopened_in`, `imports` and `calls-name`. The human relation CLI retains its exact
previous allowlist; discovery of `proves` does not make it human-declarable.
Relations remain directed from the event subject to their target. Their identity
uses source ID, predicate and target ID. An omitted relation status inherits the
current event's status, never the source entity's historical maximum authority.

The event reader continues to accept unknown kinds and predicates that match the
existing wire syntax. Existing extension histories must reconstruct with identical
bytes, event IDs and hashes. This descriptor is not a new strict admission profile.
Compatible producer/consumer adoption is a subsequent PM-001 unit.

## Provenance, authority and lifecycle

`provenance` remains an extensible object. Existing producers conventionally provide
`producer` and `source`; these fields are described as recommended, not falsely
claimed to be required by the legacy reader. Artifact schema/digest, legacy event
hash and preserved-source-event references retain their existing meanings. Actor
`kind` is required by the reader; `id` is optional. Missing provenance is not inferred.

DECLARED, INFERRED, OBSERVED and VERIFIED remain distinct. A hash chain establishes
integrity of recorded assertions, not correctness of the asserted software behavior.
Runtime observations, LLM output and self-asserted metadata confer no Proof authority.
Replacement assertions retain their own status; relation declarations do not replace
the source entity. Existing Proof/Guard authority checks remain in their own boundary.

The shared lifecycle function exactly retains the current projection: event suffixes
`.superseded`, `.retired` and `.resolved` yield `inactive`; otherwise explicit payload
`lifecycle` values `active`/`inactive` are used, with `active` as the default. A
`supersedes` relation alone does not retire its source. Rich confirm/reject/retire
commands and complete supersession semantics remain PM-006; this unit neither
silently invents them nor changes historical projection results.

## Demonstrated gap and regression gates

The baseline command exits 2 with `invalid choice: contract`. Status, relation CLI
and lifecycle rules were defined separately, with no versioned consumer descriptor.
Five new tests initially report one failed public-CLI assertion and four missing-module
errors. This is a missing-interface reproduction, not a newly demonstrated security bug.

The regressions exercise the public module entry outside Git in both languages,
the canonical concept/legacy-kind mapping, the preserved human relation boundary,
reconstruction of extension histories and suffix precedence, and independence of
returned metadata from live validation rules. Existing JSON/history and authority
regressions remain required. Installed wheel and standalone binary language journeys
also exercise the new command and compare its English/French JSON outputs.

Required gates: targeted Continuity, full platform/package matrix, ProofBench,
ContinuityBench 10k budgets, integrated smoke, code review, and fresh exact-main after
qualified PR merge. Current SHAs, workflow results and artifact digests belong in #74.
No HUMAN PASS or full PM-001 completion is asserted here.

## Boundary review

The export contains static contract metadata only: no project paths, raw source,
events, prompts, commands, secrets or Portal payloads. It performs no file mutation,
network call or executable deserialization. Existing runtime rules are imported from
one neutral module with no added runtime dependency. Hot journal loops receive the
same patterns, limits and set membership checks; metadata construction occurs only
when requested. State schema and cache anchors remain unchanged because projection
and admission semantics are unchanged. Final performance qualification remains a gate.
